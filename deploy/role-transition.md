# Переход существующего volume

Процедура предназначена для выделенного кластера Stage 10 с приложением
в схеме public на ревизии 0001_storage. Остановите клиентов и сделайте
резервную копию, включая роли. Проверьте её восстановление на отдельном volume.
Сверьте Compose project, имя подключаемого volume, базу и текущего владельца.
Проверьте дополнительные схемы, функции с SECURITY DEFINER и нестандартные
гранты PUBLIC. Для общего или изменённого кластера нужен индивидуальный план.

Сохраните прежние POSTGRES_USER, POSTGRES_PASSWORD и POSTGRES_DB в защищённом
env-файле. Прежний пользователь остаётся администратором. Добавьте два разных
случайных пароля MIGRATOR_PASSWORD и APP_PASSWORD. Имена sde_migrator и
sde_runtime должны быть свободны. Предварительно соберите новый образ.
Из каталога проекта с теми же параметрами -p и --env-file, что и при первом
запуске, выполните в Bash (dc обозначает ваш docker compose с этими параметрами):

```bash
dc config --quiet
dc build migrate
dc stop api
dc up -d --no-deps --wait db
dc exec -T db bash /docker-entrypoint-initdb.d/10-roles.sh
dc run --rm --no-deps migrate
dc up -d --no-build --wait api
curl -fsS http://127.0.0.1:8000/health/ready
```

Скрипт выполняет передачу прав одной транзакцией. Он останавливается при
существующих прикладных ролях, неожиданной ревизии или повторных связях.
Не удаляйте дубли автоматически. При ошибке миграции после успешного
изменения ролей оставьте API остановленным и разберите ошибку. Повторяйте
только миграцию. Сверьте число событий и алертов и идентификаторы контрольной
партии до возобновления записи. Прежний административный пароль был доступен старому API.
Смените его интерактивно через psql и команду \password для bootstrap-роли,
обновите защищённый env-файл и пересоздайте контейнер db с тем же volume.
Смена значения переменной сама по себе пароль существующей роли не меняет. Для возврата к исходному состоянию используйте
проверенную резервную копию на отдельном volume.

Для pytest создайте отдельную БД, владельцем которой является выделенная
роль LOGIN без административных атрибутов, членства в других ролях и доступа
к рабочим БД. Установите комментарий БД `sde:disposable-tests` и передайте
её URL через SDE_TEST_DATABASE_URL. Фикстура проверяет метку, владельца и
административные атрибуты перед созданием временной схемы.
