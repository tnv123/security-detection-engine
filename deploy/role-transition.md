# Переход на раздельные роли PostgreSQL

## Условия применения

Инструкция предназначена для существующих развёртываний, в которых API и Alembic используют общую административную роль PostgreSQL.

Поддерживается переход с ревизии `0001_storage` в выделенном кластере PostgreSQL с таблицами приложения в схеме `public`.

Если кластер используется другими приложениями, содержит дополнительные схемы, функции с `SECURITY DEFINER` или нестандартные привилегии `PUBLIC`, порядок перехода необходимо определить отдельно.

## Подготовка

Остановите запись в базу данных. Сделайте резервную копию базы и ролей PostgreSQL, проверьте восстановление на отдельном volume.

Сверьте имя Compose-проекта, подключаемый volume, имя базы данных и её владельца.

В существующем env-файле сохраните значения `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB`. Прежняя роль PostgreSQL останется административной.

Добавьте переменные `MIGRATOR_PASSWORD` и `APP_PASSWORD` с разными случайными паролями. Имена ролей `sde_migrator` и `sde_runtime` не должны быть заняты.

## Порядок перехода

Выполните команды из корневого каталога проекта в Bash:

```bash
dc() {
    docker compose -p "$COMPOSE_PROJECT" --env-file "$ENV_FILE" "$@"
}
```

Перед вызовом функции задайте переменные `COMPOSE_PROJECT` и `ENV_FILE`, указав имя существующего Compose-проекта и путь к его env-файлу.

Проверьте конфигурацию и соберите образ:

```bash
dc config --quiet
dc build migrate
```

Остановите API и запустите PostgreSQL:

```bash
dc stop api
dc up -d --no-deps --wait db
```

Создайте прикладные роли и передайте права на существующие таблицы:

```bash
dc exec -T db bash /docker-entrypoint-initdb.d/10-roles.sh
```

Изменение ролей и привилегий выполняется в одной транзакции. Скрипт прерывает выполнение, если прикладные роли уже существуют, ревизия базы отличается от ожидаемой или обнаружены повторные связи между корреляционными алертами и событиями.

После успешного выполнения скрипта примените миграции и запустите API:

```bash
dc run --rm --no-deps migrate
dc up -d --no-build --wait api
```

## Проверка результата

Проверьте состояние сервисов и готовность API:

```bash
dc ps -a
curl -fsS http://127.0.0.1:8000/health/ready
```

Для проверки количества сохранённых записей выполните:

```bash
dc exec -T db sh -c \
    'psql -X -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' <<'SQL'
SELECT 'security_events' AS table_name, COUNT(*) FROM security_events
UNION ALL
SELECT 'detection_alerts', COUNT(*) FROM detection_alerts
UNION ALL
SELECT 'correlation_alerts', COUNT(*) FROM correlation_alerts
UNION ALL
SELECT 'correlation_events', COUNT(*) FROM correlation_events;

SELECT version_num FROM alembic_version;
SQL
```

Количество записей должно совпадать с результатами аналогичной проверки до перехода. Ожидаемая ревизия после миграции — `0002_unique_events`.

Перед возобновлением записи проверьте доступность ранее сохранённых событий и алертов по их идентификаторам.

## Смена административного пароля

В прежней конфигурации административный пароль PostgreSQL был доступен API. После перехода его необходимо сменить.

Подключитесь к PostgreSQL:

```bash
dc exec db sh -c \
    'psql -X -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

Выполните команду `\password` для текущей административной роли и завершите сеанс командой `\q`.

Обновите значение `POSTGRES_PASSWORD` в env-файле и пересоздайте контейнер PostgreSQL с сохранением существующего volume:

```bash
dc up -d --no-deps --force-recreate --wait db
```

Проверьте готовность API:

```bash
curl -fsS http://127.0.0.1:8000/health/ready
```

Изменение `POSTGRES_PASSWORD` в env-файле не меняет пароль роли в уже инициализированной базе данных.

## Ошибки при переходе

Если скрипт обнаружил повторные связи, проверьте соответствующие записи. Не удаляйте их автоматически.

Если изменение ролей завершилось успешно, но миграция завершилась ошибкой, оставьте API остановленным. После устранения причины повторите только миграцию.

Для возврата к исходному состоянию восстановите резервную копию на отдельном volume. Не удаляйте исходный volume до проверки восстановленной базы.
